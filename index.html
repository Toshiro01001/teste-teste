      Como isto funciona

      O Fichário é um exemplo de sistema de cadastro: uma lista de pessoas inventadas que você pode buscar, filtrar, abrir uma por uma e aumentar com novos registros. Ele existe para mostrar o tipo de sistema que a Mil e Uma Linhas! faz. Nada aqui é real e nada é vendido ou cobrado.

      O que você pode fazer

      • Consulta: digite um nome, uma cidade ou um número na caixa de busca. A lista muda enquanto você digita. Toque em um nome para abrir a ficha completa.
      • Mais filtros: escolha a cidade, a faixa de idade e o período. As abas acima da lista separam por situação (em aberto, localizada, encerrado).
      • Baixar planilha: salva a lista que está na tela em um arquivo que abre no Excel ou em outra planilha.
      • Novo registro: cadastra uma pessoa inventada. Se algum campo estiver errado, a tela aponta qual e explica o motivo.

      Por dentro, em linguagem comum

      O sistema tem duas partes que conversam. A primeira é a tela que você está vendo, que roda no navegador sem instalar nada: a busca, os filtros, a ordenação, as páginas, as contagens e a planilha ficam todos aqui. Cada ficha e cada busca tem endereço próprio: copie o link da barra do navegador e a mesma tela abre em outro aparelho. A tela foi feita para funcionar pelo teclado e com leitor de tela.

      A segunda parte é de onde vêm os dados. Nesta versão publicada, as fichas vêm de um arquivo fixo guardado junto com o site, e o que você cadastra fica só nesta aba: some ao recarregar a página. Na versão com servidor, um programa em Java recebe os pedidos, confere cada campo, recusa o que estiver errado e explica o motivo. O projeto traz ainda o desenho das tabelas para guardar tudo em um banco de dados.

      Detalhes técnicos
      • Tela: HTML, CSS e JavaScript sem bibliotecas, sem etapa de build e sem nada carregado de terceiros. As rotas (consulta, ficha, novo registro) e os filtros ficam no endereço da página, depois do símbolo #.
      • Fontes de dados: o arquivo dados/registros.json (modo estático) ou a API em Java (modo servidor). As duas respondem às mesmas funções no código, e um teste confere que dão os mesmos resultados.
      • API (a parte do servidor que responde aos pedidos da tela): Java 17 puro, com com.sun.net.httpserver, sem framework e sem dependência externa. Rotas REST para listar, abrir, criar, atualizar e apagar registros e para as contagens. Erros de preenchimento voltam com status 400 e o motivo por campo. Os dados ficam na memória do servidor.
      • Banco de dados: o esquema SQL está em servidor-java/sql/esquema.sql e é testado em SQLite. O servidor da demonstração não usa banco; para ligar um, troca-se a classe de repositório por uma versão com JDBC.
      • Segurança: Content-Security-Policy restrita (nada externo), todo dado variável entra como texto e nunca como HTML, as mesmas regras de validação rodam na tela e no servidor, o servidor só deixa alterar dados a partir de uma origem autorizada e recusa corpos acima de 64 KB, e a planilha protege contra fórmulas injetadas. Não há login: numa publicação real, a API ficaria atrás de HTTPS com autenticação.
      • Acessibilidade e testes: navegação por teclado, leitor de tela e contraste AA conferidos por testes automatizados no Chromium (computador, iPhone 13 e tela de 320 px), além de testes da API em Java e do esquema SQL.

      O código completo e as instruções para rodar estão no README do repositório.

      O que dá para adaptar

      A estrutura é a mesma para qualquer cadastro. Mudam os campos, os filtros e as regras:

      • Estoque: produto, quantidade, depósito, validade e alerta de falta.
      • Clientes: contato, cidade, situação do atendimento e última conversa.
      • Processos: número, responsável, prazo e andamento.
      • Qualquer outro cadastro: associados, matrículas, equipamentos, chamados.

      O que esta demonstração não faz

      Não é um serviço oficial, não tem ligação com nenhum órgão público e não recebe nem encaminha informações. As pessoas, as cidades e os casos foram inventados. Em caso real, procure a polícia.
